# Asset Failure Predictor

**Transport operations tool for asset failure risk scoring, cost-per-hour (CPH), and cost-per-mile (CPM).**

A portfolio demonstration of an end-to-end ML product for operational transport fleets — including the **full Python pipeline**, **demo datasets**, and a **deployable web application**. Built from a production analytics project; all client identifiers are replaced with synthetic data for public release.

| Module | What it predicts | Model |
|--------|------------------|-------|
| **Failure Risk** | Trip-level shutdown / failure probability | Calibrated XGBoost + SHAP explanations |
| **Cost Per Hour (CPH)** | PM, GENREP, and fuel cost per engine hour | Two-stage Random Forest |
| **Cost Per Mile (CPM)** | Maintenance and repair cost per mile | Random Forest (GENREP + PM) |

> **Note:** This repository uses **synthetic and anonymized demo data**. It does not contain confidential client information.

**GitHub:** [github.com/Suhailcodeswell/asset-failure-predictor](https://github.com/Suhailcodeswell/asset-failure-predictor)

## ML pipeline

Retrain the failure-risk model on bundled demo data:

```bash
pip install -r requirements-ml.txt

# Validate inputs
python pipeline/refresh.py --check

# Full pipeline (~10–15 min): features → train → export
python unified_pipeline.py
```

See [docs/PIPELINE.md](docs/PIPELINE.md) for the full workflow, script reference, and data conventions.

## Local development (web app)

```bash
pip install -r requirements.txt
npm i -g vercel
vercel dev
```

Open `http://localhost:3000` — the app loads immediately with no login.

Or use the lightweight dev server:

```bash
python scripts/dev_server.py
```

## Features

- Trip risk predictor with calibrated probability and SHAP drivers
- Fleet dashboard with risk tiers, PM compliance, and Excel export
- Model comparison and repair pattern analysis
- CPH fleet lookup, scenario planner, and money-pit classification
- CPM unit lookup, what-if scenarios, and fleet ranking
- Pilot validation workflow

## Tech stack

- **Frontend:** HTML, Tailwind CSS, vanilla JavaScript
- **Backend:** Python serverless API (Vercel)
- **ML training:** pandas, scikit-learn, XGBoost, SHAP
- **ML inference:** Pure-Python tree walkers (no sklearn/xgboost runtime on server)

## Data privacy

All TransX/client identifiers (company names, unit IDs `R####`, hub codes `CN TOR`, shop codes, container prefixes) are replaced with synthetic labels (`AST-####`, `Hub-East`, `SHP-01`, etc.). Run `scripts/sanitize_portfolio_data.py` to re-anonymize JSON fleet data after updates.
